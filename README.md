# bill-watch-feed

`bill-watch` 미니앱이 읽는 데이터 저장소. **사람이 직접 커밋하지 않는다** — GitHub
Actions(`.github/workflows/poll.yml`, 아직 미구현)가 열린국회정보 Open API를 주기적으로
조회해 여기에 커밋한다. 공개 저장소인 이유: 미니앱은 서버가 없는 정적 번들이라, 클라이언트가
인증 없이 `raw.githubusercontent.com` 으로 직접 fetch 해야 한다(`minute-vote` 는 쓰기가 필요해
Upstash 를 썼지만, 여기는 읽기 전용이라 공개 git 파일로 충분하고 더 싸다).

## 상태 (2026-08-13)

**목데이터만 있다.** 열린국회정보 API 인증키를 아직 발급받지 못해 실제 폴러를 못 붙였다.
`bills/sample-2200001.json` 은 스키마를 보여주기 위한 손으로 쓴 예시이고, 실제 API 응답
필드명과 다를 수 있다 — **키를 받으면 실제 응답을 보고 스키마를 다시 확정한다.**

## 스키마 (설계안 — 실물 확인 전)

### `bills/<의안ID>.json` — 의안 하나 = 파일 하나

같은 의안에 새 이벤트(위원회 심사 → 법사위 → 본회의 의결)가 생기면 **파일을 새로 만들지
않고 `events` 배열에 이어붙인다.** 이게 "같은 법에 대한 이벤트는 이전 게시글에 계속
쌓인다"는 요구사항의 구현이다.

```json
{
  "billId": "2200001",
  "title": "○○법 일부개정법률안",
  "committee": "행정안전위원회",
  "proposer": "홍길동 의원 등 10인",
  "assemblyTerm": 22,
  "events": [
    { "date": "2026-08-01", "stage": "발의", "detail": "...", "sourceUrl": "..." },
    { "date": "2026-08-10", "stage": "입법예고", "detail": "...", "sourceUrl": "..." }
  ]
}
```

`stage` 는 국회 의안 처리 단계 중 하나다: `발의` · `입법예고` · `위원회심사` · `법사위심사` ·
`본회의의결`. (법령 개정 신구대조·정책 카테고리는 2단계 범위라 여기 없다 — 착수 시
`stage` enum과 파일 스키마를 확장해야 한다.)

### `index.json` — 최신 이벤트 피드 (미니앱 홈 화면용)

폴러가 매 실행마다 전체를 다시 생성한다. 최근 N개, 최신순.

```json
{
  "generatedAt": "2026-08-13T09:00:00+09:00",
  "items": [
    { "billId": "2200001", "title": "○○법 일부개정법률안", "stage": "입법예고", "date": "2026-08-10" }
  ]
}
```
